# ADR-0003: 单主干流式 Fork 异步控制与关键帧锚定语义图片图数据库

- 状态：提案 / 架构演进设计（2026-11-21）
- 关联文档：[ROADMAP.md](../ROADMAP.md)、[TASKS.md](../TASKS.md)、[ADR-0001](0001-livo-yaw-pipeline-overlap.md)、[ADR-0002](0002-embodied-agent-async-and-map-outlook.md)

## 1. 背景与现场痛点

在 DynaNav 双层全房间自主探索实测中，当前“回合制单航点（下发 `goto` → 到达停稳 → 读多图思考 10~30 s → 再下发下一航点）”暴露出三类结构性瓶颈：

1. **走停节奏过慢且诱发长停滞发散**：机器人在低特征白墙/窄角停驻等待 Agent 思考数十秒时，带噪 IMU 偏置游走叠加退化观测极易导致前端发散；同时大量直线走廊不需要高频重思考。
2. **行进中缺乏语义级实时抢占**：机器人按长航点推进期间，镜头扫到新敞开的门洞、楼梯正入口或净空压低的斜顶死角时，只能等到旧航点走完或超时卡住才被主 Agent 发现。
3. **长程探索记忆与上下文膨胀**：纯靠对话历史保存数百帧 RGB 和三维坐标会迅速撑爆上下文并产生空间幻觉；即便 SLAM 彩色三维重建很快，也只包含几何点云与像素，缺乏按“走廊 / 房间 / 楼梯间”组织的语义图谱，且无法反哺后端消除几何退化回环误配。

本 ADR 承接 [ADR-0002](0002-embodied-agent-async-and-map-outlook.md)，给出面向在线具身探索的统一控制与地图记忆架构。

## 2. 架构一：单主干 + 阅后即焚流式 Fork 哨兵（Streaming Speculative Fork）

### 2.1 不拆割裂的双 Agent，而是同一 Agent 的两种推理形态

几何避障、步态稳定与动态障碍躲避不需要大模型高智能，必须继续留在底层实时栈；大模型仅负责**视觉语义判读**与**任务级探索决策**。因此无需维护两个状态割裂的独立 Agent，而采用 **单主干（Main Thread）向短命哨兵（Ephemeral Fork）单向分叉** 的统一形态：

```text
[SLAM 后端 + 语义拓扑摘要] ──(每步刷新精简前缀)──► [Agent 主干 (共享 KV-Cache)]
                                                       │
                                                       ├── 下发宏动作: goto(沿走廊推进) [epoch=k]
                                                       │     ├─ tick 1 ─► Fork (无思考, ≤20 tok) ─► "CONT" (阅后即焚，不写回主干)
                                                       │     ├─ tick 2 ─► Fork (无思考, ≤20 tok) ─► "CONT" (阅后即焚，不写回主干)
                                                       │     └─ tick 3 ─► Fork (无思考, ≤20 tok) ─► "STOP: 左侧发现未访开门房间"
                                                       │                                                   │
                                                       ◄──────── 仅将触发干预的 1 帧 + 理由合回主干 ────────┘
                                                       │
                                                       └── 主干决策 (按需思考) ─► 更新房间状态 ─► 下发新宏动作 [epoch=k+1]
```

- **共享 KV-Cache 继承记忆**：Fork 分支直接复用主干前缀（含当前任务目标、已访/未访房间拓扑摘要、当前宏动作意图），天然知道哪些门洞已经进过，不会反复误触发。
- **阅后即焚防上下文膨胀**：行进中占 90% 以上的 `CONT` 帧在返回后立即销毁，**绝不写回主干对话历史**；只有触发中断干预的关键帧才合并回主干。

### 2.2 并发窗口、防乱序与延迟约束

1. **节拍匹配延迟与位移（避免盲目 10 Hz 放大并发）**：
   - 若单次无思考推理延迟 $L \approx 0.5\text{–}0.8\text{ s}$，按 `0.1 s` 固定 Fork 会产生 5~8 路高度重复画面的并发请求；
   - 建议采用**时间 + 位移混合触发**（例如每 `0.4~0.5 s`，或位移 $\ge 0.3\text{ m}$ / 航向变化 $\ge 10^\circ$ 时 Fork 一次），将并发窗口压在 `2~3` 路。
2. **Epoch 抢占与单调帧号防过时覆盖（Stale Frame Preemption）**：
   - 每次主干下发新宏动作或采纳干预时递增 `action_epoch`，所有旧 `action_epoch` 的在途 Fork 返回立即作废；
   - 同一 `action_epoch` 内为每个 Fork 绑定单调 `frame_seq` 与过期时间 `max_age_s`（如 `1.2 s`）：若更新帧已判定通过或超龄，较慢返回的旧帧不得再抢占当前执行。
3. **严格输出与输入克制**：
   - **输入**：仅喂 `1` 张压缩前视 RGB（如 `336×336`）+ `1` 张以机器人为中心的极简 2D 局部顶视小地图（如 `10 m × 10 m`，含墙体、已走轨迹、未知灰区、目标箭头；若有先验平面图则直接叠画房间号与已访状态）。
   - **输出**：关闭思考，硬截断在 `1~20 token` 的受控枚举（如 `CONT`、`STOP_NEW_DOOR`、`STOP_STAIRS`、`STOP_DEAD_END`、`BEAR_LEFT`、`BEAR_RIGHT`）。

### 2.3 三层控制职责红线（System 0 / 1 / 2）

| 层级 | 频率与实现 | 职责 | 严禁越界项 |
| --- | --- | --- | --- |
| **System 0（本地控制/安全）** | `50~200 Hz`，C++/Python（SCAN + RoboGauge + 安全门） | 物理避障、局部 B 样条跟踪、跌倒/碰撞保护、动态近身拦截 | — |
| **System 1（流式 Fork 哨兵）** | `2~3 Hz`，无思考短输出 Fork（复用主干前缀） | 行进中语义级抢占中断（发现新门洞、楼梯口、低斜顶死角、目标物体）与粗略方向提示 | 禁止替代 50 Hz 物理避障或直接写底盘速度 |
| **System 2（主干决策）** | 按需低频（航点到达或被 System 1 抢占时唤醒） | 阅读拓扑地图/4 视图、更新语义节点状态、规划长程探索宏动作 | 禁止把高频监控帧写入主干历史 |

## 3. 架构二：关键帧锚定的层次化语义拓扑图与图片数据库

### 3.1 地图理解由外部后端维护，而非大模型对话记忆

全局 3D 几何与地图拓扑由 SLAM 后端及语义层统一维护，结构上组织为**层次化 3D 场景图（Building → Floor → Corridor / Room / Stairwell → Door / Landmark）**：

```text
Building
 ├── Floor 1
 │    ├── Corridor_1A   (keyframe_ids, representative_rgb[], semantic_summary)
 │    ├── Room_101      (keyframe_ids, representative_rgb[], objects[], visited)
 │    └── Stairwell_1to2 (connects Floor 1 <-> Floor 2)
 └── Floor 2
      └── ...
```

- **核心锚定原则**：所有语义节点、门洞边与 System 2 看过的精选代表图，一律**绑定到 SLAM 后端的 `keyframe_id`**（复用 `localization_mapping/semantic_mapping/` 的锚点更新机制），而非写死绝对 3D 坐标。每当后端位姿图回环优化更新关键帧位姿，所有房间节点、物体与图片位置自动随整栋地图整体重投影，保持几何与语义严格一致。
- **零额外成本入库**：System 2 在决策点本来就会阅读关键 RGB 图像，只需在输出决策时顺带产出对应节点归类（走廊/房间/楼梯）与简短语义标签，写入图数据库。

### 3.2 图片数据库反哺 SLAM 后端分类与位姿优化（双向闭环）

挂在走廊/房间节点下的精选代表图数据库不仅是 Agent 的外部长期记忆（按房间节点召回历史代表图与最新坐标，实现具身记忆 RAG），还可以反向增强 SLAM 后端：

1. **视觉 + 语义联合回环检索与误配门控**：
   - 对代表图提取轻量本地视觉描述子（衔接 `exp/loop-visual-retrieval` 路线）并结合节点语义类别/楼层标签；
   - 过滤无纹理白墙低特征帧的无效高频回环，拒绝跨层或跨语义类别的对称走廊几何误配，强化红门大厅、消防设施、门牌等高辨识度场景的跨层大回环。
2. **语义地标与房间一致性因子**：
   - 对多次观测到的静态显著地标（门框、消防箱、标牌、楼梯拐角）或封闭房间内的墙面/平面结构，可作为辅助约束因子注入后端位姿图优化。

## 4. 配套 SLAM 后端基础约束（与具身停驻特性耦合）

结合带噪 IMU 双层实测暴露的真实失效模式，在叠加在线流式控制与语义图之前，几何 SLAM 后端需先补齐三项基础约束：

1. **思考停驻期 ZUPT / 静止位姿锚定约束**：利用 Agent 思考或等待决策时的物理静止窗口（结合零速检测与足端支撑状态），在前端/后端注入静止相对位姿零变动约束并趁静止窗口收敛 IMU 零偏，彻底消除“低特征墙角长停滞诱发漂移发散”。
2. **重力对齐先验（Roll / Pitch 强约束）**：在 6-DoF ICP 回环与位姿图边中引入重力水平方向强先验，防止窄角低顶退化点云将局部姿态配歪数度、拖垮整片局部地面。
3. **原地/近邻过密回环抑制**：限制同地点低位移关键帧的高频重复回环边，防止单一退化角落的错误边主导全局位姿图。

## 5. 分阶段落地顺序（不越层、先几何后流式）

1. **阶段 A（Phase 4 当前重点）**：基于完整双层全房间 13 话题数据与坏例数据包，先完成纯几何后端收敛（ZUPT 停驻约束 + 重力 Roll/Pitch 先验 + 过密回环抑制 + 三路回环对照）。
2. **阶段 B（外部语义拓扑记忆层）**：在 `localization_mapping/semantic_mapping/` 与 `backend/` 之间建立基于 `keyframe_id` 的轻量房间/走廊拓扑节点与代表图索引，支持回环后自动重投影与面向 Agent 的极简摘要导出。
3. **阶段 C（流式 Fork 看门狗原型）**：在 `scripts/explore_waypoint_client.py` 之上构建薄的流式看门狗层，复用现有 `goto` / `cancel` 接口实现 `action_epoch` 抢占、`(frame_seq, max_age_s)` 防乱序与 `2~3 Hz` 阅后即焚 Fork，再逐步向低延迟 IPC 演进。
