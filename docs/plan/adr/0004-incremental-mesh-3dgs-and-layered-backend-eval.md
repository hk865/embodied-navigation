# ADR-0004: 面向 FAST-LIVO2 的增量 Mesh / 3DGS 重建演进与三层 SLAM 后端评测口径

- 状态：提案 / 架构演进与评测规范（2026-11-21）
- 关联文档：[ROADMAP.md](../ROADMAP.md)、[TASKS.md](../TASKS.md)、[ADR-0002](0002-embodied-agent-async-and-map-outlook.md)、[ADR-0003](0003-streaming-fork-control-and-semantic-scene-graph.md)

## 1. 背景

在推进 Phase 4 SLAM 后端优化与多楼层数据集录制过程中，明确了两项需要制度化沉淀的设计：

1. **后端评测口径标准化**：仅看单条最终轨迹的全局 RMSE 无法揭示“哪一条回环把 Z/姿态拉偏”“在线控车时每一秒真实精度如何”“历史地图在反复回环重优化中是否剧烈抖动”。需要统一的三层轨迹评测体系，作为 Phase 4 及后续全部后端改造的唯一打分尺。
2. **几何表达向 3D Mesh / 4D 动态地图 / 3DGS 的演进路线**：FAST-LIVO2 天然产出带精确尺度、局部平面法向与 RGB 颜色的点云；如何在不干扰当前几何后端收口的前提下，为未来 Real-to-Sim 仿真资产导出、语义对象切分与照片级 3DGS/2DGS 重建预留清晰的数据与接口契约。

## 2. 三层 SLAM 后端离线轨迹评测规范（Phase 4 立即落地）

后端消费同一份离线关键帧包与真值时间轴（`$PROJECT_DATA_ROOT` 下的 `truth_scoring_stream.jsonl`）时，统一输出以下三层评测结果，默认纯 CPU 向量化（仅依赖 `numpy` / `scipy`，单次全套耗时 `< 1 s`，存储压缩 `.npz` `< 15 MB`），并同步导出标准 TUM 轨迹以兼容第三方 `evo` 交叉核验：

### 2.1 第一层：两条代表轨迹的标准标量指标
同时评估 **① 在线因果轨迹** $T_{\text{online}}(t) = C(t)\,T_{\text{odom}}(t)$（反映实时导航控车精度）与 **② 终图优化轨迹** $\{T_{\text{final}}(k)\}$（反映全包闭合后的最终建图精度），在 **首帧 SE(3) 对齐** 与 **全轨迹 SE(3) Umeyama 对齐** 两种口径下输出 `RMSE / Mean / Median / P95 / Max`：
- **ATE**（绝对平移误差，分 `3D / XY / Z`）；
- **AOE**（绝对旋转误差，分 `总旋转角 / Roll / Pitch / Yaw`）；
- **RTE**（相对平移误差，多窗口如位移 `1 m / 5 m / 10 m` 或时间 `1 s / 5 s / 10 s`）；
- **ROE**（相对旋转误差，同上多窗口）。

### 2.2 第二层：逐关键帧演化曲线（Per-Keyframe Optimization Curves）
后端每接纳第 $k$ 个关键帧（尤其每次触发回环重优化时）产出截至当前的历史位姿图快照 $\mathcal{T}^{(k)} = \{T^{(k)}(1), \dots, T^{(k)}(k)\}$，对其计算 `mean / rmse / max` 的 `ATE / AOE / RTE / ROE`，以关键帧序号或仿真时间为横轴形成演化曲线，直接量化每条回环的正收益或负作用。

### 2.3 第三层：历史位姿的逐秒收敛分布（Per-Second Revision Distribution）
固定历史采样时刻 $t_i$，追踪其在后续优化步 $k \ge i$ 中的位姿误差序列 $\{e^{(k)}(t_i)\}$，统计每个 $t_i$ 的 **中位数、IQR 四分位带、P5–P95 置信带与最大跳变幅度**。带宽越窄且越早收敛到零线，代表后端历史一致性越稳健，不反复撕扯已建地图。

### 2.4 离线回放缓存原则
为避免调参时反复扫描 50–90 GB 的原始 MCAP，评测工作流先执行一次只读抽取，将关键帧点云、前端里程计、IMU 状态与真值时间轴整理为轻量离线关键帧缓存（约 `200–500 MB`），后续所有后端对比实验均基于同一份缓存复现。

## 3. 远期几何重建演进：从平面面元到增量 Mesh、4D 动态与 2DGS/3DGS

### 3.1 点到平面 → 增量三角网格（Mesh）与物体切分
- 点到平面 ICP 与 FAST-LIVO2 VoxelMap 中的局部平面本质上是离散面元（Planelet）；为其补全顶点-边拓扑即可得到连续三角网格。
- **更新机制（不退回原始点云重算）**：
  - **子图稀疏 TSDF + 增量 Marching Cubes**（参考 Voxblox / nvblox / Voxgraph / Kimera-PGMO）：射线穿透自动冲刷移走物体的占据权重，回环优化通过移动关键帧子图与局部网格形变（PGMO）保持一致；
  - **LiDAR 切平面直接增量三角化**（参考 ImMesh）：保留门框与楼梯台阶的锐利建筑棱角。
- **对象切分与 Real-to-Sim**：在网格对偶图上依据法向突变与语义标签割边，将门、桌椅、墙体拆分为独立网格，可直接导出 `.obj / .usd` 作为 Isaac Sim 仿真与碰撞资产。

### 3.2 4D 时空动态地图（3D + 时间）
- **短时动态剔除（秒级）**：前端或建图前分离瞬时运动点（参考 M-detector / Dynablox / ERASOR），避免行人残影污染静态网格与回环子图；
- **长时半静态变化（分钟至天级）**：参考 Khronos 4D 度量-语义场景图，为语义节点与物体维护 `[首次观测, 消失]` 生命周期，与 [ADR-0003](0003-streaming-fork-control-and-semantic-scene-graph.md) 的关键帧语义图天然衔接。

### 3.3 FAST-LIVO2 + 2DGS / 3DGS 结合潜力
- 纯视觉 3DGS 在低纹理室内白墙易发生深度塌陷与尺度漂移；FAST-LIVO2 已提供厘米级精确尺度的彩色点云、局部平面法向与去畸变位姿，可直接初始化贴合建筑表面的 **2D 扁平高斯面片（2DGS / Gaussian-LIC 思路）**，再利用相机 RGB 的可微光度梯度联合精修外观与表面几何。
- 本项目当前录制的 13 话题 MCAP（原始 32 线 RTX LiDAR + 标定 RGB 相机 + 带噪 IMU + 标定外参）已满足直接输入 2DGS / 增量 Mesh / 4D 建图管线的完整数据契约；若后续引入百万点云 Chamfer 重建误差或视觉特征批量提取，可在离线评测脚本中按需接入 GPU 加速库（PyTorch / Open3D-CUDA / CuPy），核心 CPU 轨迹评测与单元测试保持零 GPU 依赖。
