# ADR-0002: 具身 Agent 异步行动、语义/动态地图管理与热路径演进备忘

- 状态：提案 / 远期演进备忘（2026-11-20）
- 关联文档：[ROADMAP.md](../ROADMAP.md)、[TASKS.md](../TASKS.md)、[ADR-0001](0001-livo-yaw-pipeline-overlap.md)

## 1. 背景

本项目最终面向**具身智能 Agent 导航**，而不仅是传统静态 SLAM 建图与点对点跟随。随着 Phase 3 干净底座落地并准备进入 Phase 4（SLAM 后端三路对照），有三个面向未来的架构方向需要提前记录，避免后续局部改造互相冲突：

1. **思考与行动并行（异步具身执行）**：Agent 推理/规划（VLM/LLM、多步语义推理、前沿评估）耗时通常在秒级；若机器人每次都“停下来等 Agent 想完再动”，探索效率极低，需要支持 **Agent 在思考的同时机器人持续平滑执行当前段或安全巡航，并在新决策到达时无缝抢占/续接**。
2. **语义 + 动态地图管理与后端控制协同**：传统 SLAM 后端只管几何位姿图和静态点云；面向具身 Agent 时，地图需要同时承载**几何回环修正、语义对象锚点随回环重投影、动态障碍生命周期管理（短暂占据与静态结构分离）**，且后端位姿修正如何平稳注入规划与控制，不能引发局部轨迹跳变。
3. **Python 原型层 vs C++ 热路径分工**：当前核心算法（FAST-LIVO2、SCAN、PCT A*）已是 C++，但仿真桥、编排器（`pct_scan_worker`）、SLAM 后端原型（`localization_mapping/backend/`）和语义层使用 Python。Python 利于快速迭代与对接 Isaac Sim / Agent 生态，但在高频点云处理、大地图管理与实机部署时存在 GIL 与单线程阻塞瓶颈。

## 2. 当前阶段原则（Phase 4 期间暂不提前重做）

- **先收敛几何后端再叠加语义/动态**：Phase 4 优先用同输入录包查清 SLAM 后端参数与三路回环方案的真实效果，暂不在不稳定几何底座上叠加在线语义/动态写回。
- **保留七层清晰边界**：Agent 介入层继续通过结构化航点/查询接口与下层交互，不越层直写速度命令、不读取仿真真值；新增自有 Python 模块默认补齐清晰中文注释，便于人工审阅与后续移植。

## 3. 未来演进方向（供分阶段细化为独立 ADR）

1. **异步并发探索协议（Think-While-Acting）**：
   - 将当前“单航点停顿等待”扩展为**可抢占航点队列 / 前瞻缓冲（Lookahead Buffer）**：控制器持续跟踪当前活跃腿，Agent 后台基于最新 `observation` + 增量语义图思考下一目标，支持热替换后续航点与安全取消；
   - 配合消除文件邮箱轮询延迟（从 JSON 文件演进到低延迟 IPC / ROS Action），缩短抢占响应时间。
2. **面向 Agent 的分层地图管理**：
   - **几何层**（后端 SLAM 关键帧 + 位姿图）负责全局一致性，回环优化后通过统一版本/锚点触发语义层对象重投影（复用 `semantic_mapping/core.py` 的 `update_anchor` 机制）；
   - **动态层**与静态几何层分离，动态物体不写入长期回环子图与静态语义锚点，仅注入局部避障窗口；
   - **后端控制协同**：评估 `CorrectionAdmission` 修正量何时从“只读发布”接入规划与控制参考系，防止回环跳变拉扯正在跟踪的局部 B 样条。
3. **热路径渐进 C++ 化边界**：
   - 保持顶层 Agent 编排、离线分析与 Isaac Sim 脚本在 Python；
   - 当 SLAM 后端方案定型或进入实机/高帧率阶段时，优先将 `localization_mapping/backend/` 的体素降采样、ICP 配准、地图检索与 `pct_scan_worker` 点云转发/体素统计下沉至 C++（或 pybind11 扩展）。

## 4. 重访触发条件

1. Phase 4 三路 SLAM 后端对照得出明确结论并合入主线；
2. 启动在线 VLM/Agent 连续长程探索（需要“边想边走”减少停顿时间）；
3. 恢复 `ref/dynanav-dynamic-pedestrian` 动态行人场景或规划实机部署。
