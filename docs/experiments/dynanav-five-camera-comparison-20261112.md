五台已完成真实 Isaac 采集与原生视觉旁路回放：**保持现有约 82.4° 水平视场，朝向 0/72/144/216/288°**。每路都获得有效图像和视觉修正。六台保留为对照，没有作为最终数量要求，也没有切换正式定位默认配置。

后续已经完成[四台 120° 的真实静止对照](dynanav-four-camera-120-comparison-20261112.md)，包括原生内参、实际 patch 中心、深度支持和资源比较；以下保留五台试验当时的结论。

这次结果支持继续评估五台作为 DSH 环视观察方案；若还要求连续全向视觉约束，跟踪裁边会带来额外盲缝，不能只看原图视场相加。

## 实际相机参数和“有效视场”

现有相机为零畸变理想 pinhole，512×512，主点 (256,256)，原生参数 `focalLength=24`、横/纵 aperture 均为 42，换算 `fx=fy=292.5714px`。所有 199 个接受帧都通过原生 CameraParams 的 pinhole、分辨率、焦距、aperture、offset 和单位门验。

使用当前 Isaac 自带的 `pxr.Gf.Camera` 另行检查，Perspective 模型返回 **82.371849° 水平视场**。它不是 120°。USD 焦距与 aperture 属性有自己的场景单位约定，这里依据相同单位比值计算，不能仅凭代码中 `MM` 常量名把它当成实体相机镜头标定。[OpenUSD Camera 属性与单位](https://openusd.org/dev/api/class_usd_geom_camera.html)

两种有效范围需要分开：

- **DSH 图像**保留整个 512×512，模型上约 82.37°×82.37°，不裁 80px。
- 当前生产参数和本次旁路都使用 `patch_size=8`、四层 pyramid。原生 `VIOManager::initializeVIO` 的 `border=(8/2+1)*2^4=80px`，`isInFrame` 排除各边 80px。因此**特征中心**可用宽度是 352px，对应约 **62.059° 水平范围**，正方形中心区域约占原图面积 47.3%。实际还要通过纹理、法向、深度、遮挡和匹配检查。

62.06° 是当前算法的中心选择范围，不能说镜头只拍了 62°，也不能把 82° 原图等同于 82° 都能产生视觉更新。80px 保护多层 patch 采样，本轮没有降低它或放宽安全/新鲜度门限。

## 四台 120° 与更少相机的几何比较

在相同 512×512、相同 80px border 的理想针孔模型中：

| 布置 | 朝向间隔 | 原图相邻远场重叠 | 特征中心 HFOV | 特征中心相邻远场重叠 | 中心像素/度 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 3×140°，候选 | 120° | 20.00° | 124.21° | 4.21° | 1.63 |
| 4×120°，优先候选 | 90° | 30.00° | 99.95° | 9.95° | 2.58 |
| 5×82.37°，本次实测 | 72° | 10.37° | 62.06° | **-9.94°，有缝** | 5.11 |
| 6×82.37°，已有实测 | 60° | 22.37° | 62.06° | 2.06° | 5.11 |

表中重叠只指远场、无遮挡、相机光轴水平等理想条件。四台 110° 在当前裁边下仅有约 88.95° 特征中心范围，仍小于 90° 间隔；四台 115° 约 94.36°，余量也较小。三台需要更广视场；例如 140° 只是刚给裁边后留出少量远场重叠，150° 会增加余量，但在相同像素数下中心细节更稀疏。

**四台 120° 在模型层面是合理候选。** 保持 aperture 42 时，focalLength 应约为 12.12435565，当前 SDK 的 `Gf.Camera.GetFieldOfView` 实际返回 120.0°。目前 capture 仍明确固定原 24/42 参数，计数选项不会偷偷将它改为 120°；四台广视场真正采集时，还需同时参数化 renderer、原生校验与内参，并验证更广视场下的跟踪。当前未实测三/四台广视场，不能宣称其遮挡或定位效果已通过。

也不能把理想 pinhole 直接当作实体广角/鱼眼镜头。Isaac 的 pinhole/fisheye 模型有各自参数；如果使用镜头畸变 schema，投影参数来源也需一致。[NVIDIA 相机模型文档](https://docs.isaacsim.omniverse.nvidia.com/6.0.0/sensors/isaacsim_sensors_camera.html)

此外，当前相机安装在 base 周围半径约 0.3m 的位置，近场不能使用“同一点发出的扇形”近似。按实际这类径向安装，在距 base 中心 2m、与相机同高的理想无遮挡圆周上，采样得到：

| 布置 | 原图可见方位总角度 | 特征中心可用方位总角度 |
| --- | ---: | ---: |
| 3×140° | 360.00° | 326.91° |
| 4×120° | 360.00° | 347.08° |
| 5×82.37° | 355.15° | 265.95° |
| 6×82.37° | 360.00° | 319.14° |

这些是安装几何推导/采样，**没有**加入机器人、楼梯、墙体遮挡，也不是实际空间覆盖率。改变安装半径/高度和位置，有时比简单增加相机数量更值得测试。

## 每路实际视觉观测

使用同代冻结数据分别回放固定曝光及每帧独立曝光 `N(1,0.1)`。沿用原生 normal、四层 pyramid、私有 patch 历史。公共物理协方差来自真实 native 19D 状态的 18D 边缘分布，曝光不跨相机共享；没有使用 ROS unavailable covariance。模型协方差仍未完成统计校准。

每模式处理 15 个时刻，首帧建缓存，后续每路 **14/14** 都有 retained numerical visual update。

| 方向 | 固定曝光累计 tracked point-frame | 独立曝光累计 tracked point-frame | 19.3s 最细层有效像素项，独立曝光 |
| --- | ---: | ---: | ---: |
| 0° | 1,466 | 1,467 | 7,936 |
| 72° | 1,161 | 1,161 | 6,080 |
| 144° | 525 | 524 | 2,816 |
| 216° | 481 | 482 | 2,240 |
| 288° | 1,174 | 1,174 | 6,336 |

累计 tracked 实例约为固定曝光 4,807 / 独立曝光 4,808；六台对照分别为 5,679 / 5,667。数量减少约 15%，但朝向和实际采样不同，不能把计数差直接解释为定位精度下降。每个像素项也不构成统计独立观测。

最后时刻独立曝光的 photometric MSE 依次约为 12.0081 / 11.8187 / 5.8700 / 5.7316 / 5.2023，单位是灰度强度平方。它不是米制误差，五/六台的后向相机角度也不相同，不能做逐相机同图精度排名。

两模式都验证：所有快照在旁路执行前后完全不变，五路中的前相机与独立单前相机 control 的 pose increment 和物理 covariance 差异为 0。两个细节日志均写出 840/840 记录，0 丢弃、0 I/O 错误。CI 仅生成离线诊断，`confidence_calibrated=false`、`estimator_feedback_enabled=false`。

对照为上一轮成功的六台 native 快照运行，场景、传感器类型、分辨率、20s 预算和同一隔离核心保持一致：

| 指标 | 五台 | 六台已测 |
| --- | ---: | ---: |
| 成功 run 总墙时 | 82.47s | 87.99s |
| 主循环墙时 | 43.3909s | 46.2863s |
| 20s/主循环墙时 | 0.4609 | 0.4321 |
| 整卡约 1s 采样显存峰值 | 6,510MiB | 6,753MiB |
| 机器人原生接受帧总数 | 995 | 1,194 |

本次主循环墙时少 **6.26%**，整卡采样峰值少 **243MiB**。这些是短时单次结果，未随机化/重复，后台 CPU 编译或负载、shader warmup 和时序未严格固定；整卡还包含桌面，不能把差值当成稳定或完全因果的性能增益。首次失败的成本单独保留，没有计入成功主循环指标。

相同分辨率下，五台机器人图像的名义像素数比六台少 16.7%；若包含不变的 overview，renderer 像素预算仅少约 14.3%。共享 LIO、IMU、物理、overview、ROS 和快照成本都仍存在。三/四台更广视场还可能看到更多几何、产生更多候选 patch，不能按台数线性推算完整 GPU 或 VIO 成本。

四台 120° 在相同 512px 下中心像素/度约为当前的一半；若用接近 1024px 恢复相似中心角分辨率，四台像素总量反而约为当前六台 512px 的 2.67 倍。因此数量、视场、分辨率需要一起比较。
