## 1. 结论摘要（对应要求的 7 点）

1. **输入新鲜度适配器是纯 pass-through，真实判定在调用者**：`common/input_freshness.py:8-12` 五个适配器都只 `return original_*`，自身没有阈值；`enabled()`（`:2-6`）仍会把任何重新开启 `r73_minimal_diagnostic_baseline` 的 profile 变成 `ValueError`，当前所有配置都是 `{'enabled': false}`，因此历史“诊断期放宽”分支不可达。真实 TTL 在 `ros_node.py`/`base_node.py`/`pid_navigation.py`/`clock_hold.py`/`control_core.py`（pose/cloud 300 ms、raw IMU 250 ms、bridge 300 ms、paired 300 ms、stale 失败 8 s）。
2. **R97 队列预算模块只提供“拒绝 + 只读选择”，真正的容量保护在 `Admission`**：`queue_budget.selection()`（`queue_budget.py:6-14`）拒绝任何非 `2097152` 的 `R97_DIAGNOSTIC_QUEUE_BYTES`，返回 `effective_bytes=2 MiB`、`max_events=32`、`max_event_bytes=1 MiB`、`observation_enabled=False`；真实入队拒绝在 `async_admission.py:365-366`（short intake）与 `:500-511`（普通接收）。观察类 `Observation` 在 `queue_budget.py` 中不存在且分支不可达，属死代码。**2 MiB 不是“过小”的证据**：spline 单事件结构性上限约 20.6 KB（`:352-354`），32 个事件约 659 KB 小于 2 MiB，因此对 spline 而言先触发的是 32 计数上限；仅大 String 元数据才会先触发 2 MiB 字节上限。是否过严必须实测队列峰值。
3. **停车/稳定：3 mm 与 1.5 mrad 是“1 s 统计窗”的统计阈值，与 legacy 300 ms 判据是 OR 关系**：`NavigationStopWindow.SPEC`（`navigation_stop_window.py:5-13`）使用 `xy_diameter_m=.003`（3 mm）、`euler_net_change_rad=.0015`（1.5 mrad）、`euler_peak_to_peak_rad=.003`；每样本有效性仍沿用 legacy 门槛（`stop_planar_speed_mps .03`、`stop_slam_yaw_rate_radps .05`、`gyro_pose_pair_max_s .15`，`:58-62`）。释放判据在 `transition_gate.py:757-770`：`legacy OR statistical OR observed`，且统计分支仅对 `eligible_purposes` 且 `request_id`/`waypoint_index`/`dynamic_recovery=False` 的转移生效（`:759-762`）；诊断 `observed` 分支默认关闭（`configs/control/settings.json:91-93`）。**20 ms 与 300 ms 回答不同问题**：20 ms 是 pose/gyro 因果配对窗（`cascade_core.py:585-586`，配置 `maximum_gyro_pair_gap_s .02`），300 ms 是来源新鲜度/年龄（`cascade_core.py:462-472`、`clock_hold.py:16-17`、`student.py:196-204`）；另有 150 ms 是停车样本的 pose/gyro 配对（`teacher_transition.gyro_pose_pair_max_s`）。1e-9 是浮点窗口边界松弛（`navigation_stop_window.py:74,76`、`transition_gate.py:632`），不是米级几何容差；实际空间容差是 3 mm/2 mm 与 2.5 cm 级停车场捕获值。
4. **工厂校验与消费者校验是不同边界，不应当重复删除**：`speed_tiers.py` 有 4 个入口——`choice()` 工厂（`:11-16`）、`validate()` 单条记录（`:18-24`）、`configuration()` 启动期跨字段（`:32-49`）、`validate_copies()` 每帧 PID/Actor/ACK 同帧一致（`:54-62`）；`student_bounds()`/`select_profile()` 内部的 `validate()`/`configuration()` 也是公开入口的输入/结果校验；尚未证明所有调用都带有足够的已验证前提，不应先认定可删。仿真侧 `safety_state.py:29-58` 是生产工厂，`simulation_gate.py:60-97` 是安全决策入口的再校验（fail-closed）；当前 native 循环在同一进程内先调用工厂、再调用 gate，两者都必须保留。
5. **模块 env 默认值不能当作生产态**：多数模块默认 `'0'`（默认关），但 `configs/launch/settings.json:9-54` 的 `features` 把 R88/R90/R91/R92/R94/R103_*/R104/R105/R106/R110/R114/R119_*/BRIDGE_SAFETY_INGRESS/SCAN_SHORT_INTAKE 打开；`launch/main.py`（HEAD `:23-25`）先应用 `features`，再把 R87/R89/R96/R99/R107/R118_SOURCE_AGE_PROBE/MATCH_QUERY_CAPTURE 强制置 `'0'`。因此 `configs` 里 R107=1、MATCH_QUERY_CAPTURE=1 **不是**正常启动的有效值；R107 另有 `third_party/scan/plan_manage/include/plan_manage/r107_transport_probe.h:40` 的 C++ 读取点。Python 侧 `common/observation.py:48-51` 恒返回 `DisabledObservation`，通过该端口的诊断记录关闭；业务透传与 unsupported 接口异常仍保留，不能把所有 Python hook 或旁路实现一概视为无作用。
6. **DynaNav 的 `MAX_DISPLACEMENT` 默认 0.25 m 只属于采集/探针入口**：`simulation/dynanav/capture_go2_rgbd.py:153` 的断言限制相对 spawn 的 XY 位移小于 `MAX_DISPLACEMENT`（默认 0.25 m），同一条断言还含 `pos[2]>.15`、速度 `<.65`、姿态 `<.5 rad`/接触 0；入口是 `scripts/capture_dynanav.py:36-37`，作用域在 `simulation/dynanav/README.md:15` 已声明“本次未验证或调整该阈值、不能据此宣称完成长路线导航”。它不是导航阈值，不能外推到导航/控制。
7. **独立 Building 入口存在两处真实校验缺口（本轮未改，属行为修改候选，不是格式问题）**：
   - `launch/building.py:164,179` 对 `--duration` 只检查 `<=0`，**没有 `math.isfinite`**；`nan` 被接受后 `deadline=nan`（`:114`），运行循环 `while time.monotonic()-began<deadline` 立即不成立，`reason` 保持初值 `'wall_limit'`（`:76`），退出码 2；`inf` 被接受后变成无界墙钟上限（只能靠子进程退出/信号结束）。对比 `launch/main.py`（HEAD `:45-46`）已正确拒绝非有限值并有单测（`tests/unit/test_launch_cli.py:23-33`）。
   - `launch/building.py:173-177` 的 `--check` 在 `:178-189` 的参数校验（domain 1..232、duration>0、两类 lidar-gap 组合、label 字符集）之前提前 `return`，因此 `--check --domain 999 --duration nan --label '??'` 这类非法组合被静默接受。本审计用只读方式实测：`building.main(['--check','--duration','nan'])` 与 `--domain 999` 均未触发 argparse 错误，输出依赖检查 JSON 并因依赖缺失返回 2。现有 `tests/unit/test_building_entry_closure.py:57-69` 只覆盖 truth 拒绝与默认 `--check`，不覆盖上述两点。

## 4. 后续修复与清理候选（本轮全部未修改）

## 5. 运行时数据缺口与测量计划

本审计**没有任何运行时/仿真数据**，因此对“是否过严”一律不下结论。以下是后续测量需求（不改阈值）；现有快照不等于已存在可导出的峰值历史，若需增加临时诊断采样/导出，应另行明确实现与验证开销：

- **M1 静止噪声（回答表 C1 的 3 mm/1.5 mrad）**：在真实 SLAM 静止场景记录 ≥30 s 已接受的 pose+body gyro；按 `NavigationStopWindow.SPEC` 的 1 s 窗计算每窗的 `xy_diameter_m`、`xy_net_change_m`、`euler_peak_to_peak_rad`、`euler_net_change_rad`、gyro mean/rms/peak，输出最大值/P99/P50。判据：若多数窗超过 3 mm 或 1.5 mrad，说明统计分支可能很难单独通过；只要 legacy 判据成功仍可释放。应取得噪声与释放分布后再评估数值调整，并分别验证 legacy 与统计许可路径。
- **M2 队列峰值（回答 B6/B7 的 32 事件/2 MiB）**：一次完整正常路线中记录 `Admission` 的 `queue_snapshot()`/`intake_snapshot()`（`async_admission.py:280-283,828-842`）以及退出回执 `r88_async_physical_exit.json` 的 `counts`（`pid_cli` 落盘 `pid_navigation.py:2588-2591`）；统计 `queue_count`/`queue_bytes` 峰值、`r88_scan_event_queue_bound` 出现次数、事件类型分布。判据：峰值是否接近 32/2 MiB；不要凭常数大小判断；`queue_snapshot/intake_snapshot` 是瞬时状态，`close()` 先 invalidate/清理再产生退出回执，不能仅用退出时队列值或 counts 重建运行峰值和事件类型分布。
- **M3 新鲜度/Jitter 分布（回答 A5-A7、C11、H4、H6）**：在真实运行中分别采样同一 ROS 时钟域的 `current_ros_ns-header_stamp_ns` 源龄，以及单调墙钟域的 `current_monotonic_ns-received_wall_ns` 接收龄，并统计同域回调间隔、`pose_stamp_ns-gyro_stamp_ns` 因果配对差，输出 P50/P99/max；严禁把单调接收墙钟直接减 ROS header 时间戳；同时记录 `clear_guard` 清空发布周期与 `--resource-check` 时的 loadavg/MemAvailable。用于判断 300 ms/250 ms/20 ms/150 ms/300 ms 的裕量，以及至少 10 次、跨度至少 1 s、保留 1.35 s 与最大 0.3 s 间隔组合是否可满足。
- **M4 释放谓词命中率（回答 C7）**：在每个 settle 转移记录 `last_release.predicate`（`transition_gate.py:767-769`）与 `statistics`；统计 `legacy_continuous_300ms` vs `navigation_settle_statistics/v1` 的命中比例、以及“两者都未通过导致等待/超时”的次数。用于判断统计分支是否实际被使用（决定是否可简），而不是凭代码结构猜。
- **M5 Building 参数校验回归（回答 G1/G2）**：纯 Python 单测（无需运行时）：`building.main(['--check','--duration','nan'])` 应被 argparse 拒绝；`--duration inf` 应被拒绝；`--check --domain 999` 的行为应与选定语义一致。本审计已用只读方式验证当前“被接受”的事实，修复后应加断言。
